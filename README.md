# 轻途计划

中文 | [English](README.en.md)

这是一个可以在自己电脑上运行的旅行行程演示网站。它不连接 AI、服务器、数据库或实时地图，而是使用项目内置的北京、上海、广州、昆明和南京模拟数据，按照固定规则生成 1～7 天的行程。

当前状态：早期演示原型。

计划只保存在你当前使用的浏览器里。清除浏览器数据、换浏览器或换电脑后，原计划不会自动跟随。所有价格、时间、距离和地点信息都只是演示数据，不能直接作为真实出行依据。

## 项目里的文件夹有什么用

- `src`：网站本身，包含页面、计算规则、五个城市的模拟数据和样式。
- `tests`：自动检查，用来确认计算、页面和不同屏幕尺寸没有被改坏。
- `scripts`：检查五个城市数据是否完整的小程序。
- `data-pipeline`：离线数据整理工具，用来把公开来源中的结构化事实整理成网站可用数据；不包含本地数据库、虚拟环境或采集输出。
- `package.json`：记录项目需要安装哪些工具，以及可用命令。

一般使用网站时，不需要手动修改这些文件。

## 第一次运行前的准备

以下步骤按 macOS 编写。

### 1. 打开“终端”

按键盘上的 `Command + 空格`，输入“终端”或 `Terminal`，按回车。你会看到一个可以输入文字命令的窗口。

### 2. 安装 Node.js

Node.js 是让这套项目工具能够运行的基础环境。

如果电脑还没有 Node.js，请用浏览器打开 `https://nodejs.org/`，下载并安装标有 **LTS** 的版本。安装完成后，关闭终端，再重新打开终端。

复制下面的命令到终端并按回车：

```bash
node --version
```

正常结果会显示一个以 `v` 开头的版本号，例如 `v22.x.x`。如果显示“command not found”，说明 Node.js 尚未正确安装。

### 3. 安装 pnpm

pnpm 是本项目用来下载和运行工具的程序。复制并运行：

```bash
npm install --global pnpm@11.9.0
```

完成后运行：

```bash
pnpm --version
```

正常结果会显示 `11.9.0` 或同一大版本的版本号。

### 4. 进入项目文件夹

每次新开终端后，都先运行：

```bash
cd "/path/to/travel_planner_public"
```

这条命令没有输出就是正常的。它的作用是让终端进入本项目所在的文件夹。路径中的引号不能省略，因为文件夹名称里有空格。

### 5. 安装项目需要的工具

只在第一次运行，或 `package.json` 有变化时需要执行：

```bash
pnpm install
```

正常结果会出现 `Done`，并在项目中生成 `node_modules` 文件夹。下载速度取决于网络。

## 启动网站

先确认终端已经进入项目文件夹，然后运行：

```bash
pnpm dev
```

正常结果会出现类似：

```text
Local: http://localhost:5173/
```

不要关闭这个终端窗口。打开浏览器，在地址栏输入：

```text
http://localhost:5173/
```

看到“新建旅行计划”页面就说明启动成功。

### 停止网站

回到正在运行项目的终端，按：

```text
Control + C
```

终端重新出现可输入命令的提示符，就表示网站已经停止。

### 重新启动网站

重新打开终端后，依次运行：

```bash
cd "/path/to/travel_planner_public"
pnpm dev
```

然后再次打开 `http://localhost:5173/`。

## 建议的演示顺序

1. 在“新建计划”填写出发地、目的地、开始日期和结束日期。
2. 根据需要展开住宿、交通、饮食等分组；不填写时会使用默认值。
3. 点击“生成行程”，查看每日时间轴、交通、预算、风险和模拟数据声明。
4. 尝试替换、上移、下移、移动日期、锁定或删除一个景点。
5. 点击“重新生成”，确认手动修改并锁定的内容得到保留。
6. 打开“本地计划”，尝试继续编辑、重命名、复制和删除。
7. 在行程详情页点击“打印”，在浏览器打印窗口中选择“存储为 PDF”。

## 检查项目是否正常

普通使用不需要运行这些检查。修改代码后，可以使用它们确认项目没有被改坏。

检查五个城市的模拟数据：

```bash
pnpm validate:data
```

正常结果是“北京、上海、广州、昆明、南京静态模拟数据校验通过”。

运行计算和页面组件测试：

```bash
pnpm test
```

正常结果会显示所有测试文件和测试项目均为 `passed`。

第一次运行真实浏览器测试前，先安装测试浏览器：

```bash
pnpm exec playwright install chromium
```

然后运行：

```bash
pnpm test:e2e
```

正常结果会显示 `6 passed`。这个测试浏览器只用于自动检查，不影响平时使用。

生成可发布的静态文件：

```bash
pnpm build
```

正常结果会显示 `built`，并生成 `dist` 文件夹。第一版不包含在线部署功能。

## 常见问题

### 终端显示 `command not found: node`

Node.js 没有安装好。重新安装 Node.js 的 LTS 版本，然后关闭并重新打开终端。

### 终端显示 `command not found: pnpm`

重新运行：

```bash
npm install --global pnpm@11.9.0
```

### 终端显示 `No such file or directory`

通常是项目路径输入错误。直接复制本说明中的 `cd` 命令，并保留路径两侧的英文双引号。

### 浏览器打不开 `localhost:5173`

确认运行 `pnpm dev` 的终端仍然开着，并且没有按过 `Control + C`。如果终端显示了其他端口，例如 `5174`，就打开终端实际显示的地址。

### `5173` 端口已被占用

这通常表示另一个项目仍在运行。找到之前的终端窗口并按 `Control + C`，再重新运行 `pnpm dev`。也可以直接使用终端新显示的地址。

### 安装依赖时网络失败

保持项目文件不动，网络恢复后再次运行 `pnpm install`。重复执行不会删除已完成的项目文件。

### 原来的计划不见了

计划只保存在生成它的浏览器中。请确认使用的是同一个浏览器，并且没有清除该网站的浏览器数据或使用无痕模式。

### 页面显示模拟数据提示

这是正常设计。第一版故意不接入实时数据库、地图或 AI，所有可能影响真实出行的内容都必须明确标为模拟或估算信息。
